B5-2 Mini Git CLI 입력과 기대값

[사용법]
새로 실행한 mini-git 세션에서 아래 명령을 번호 순서대로 한 번씩 입력한다.
`mini-git>`는 프롬프트 표시이므로 직접 입력하지 않는다.
`<실행 시각>`은 명령을 실행한 실제 시각으로 바뀐다.
검색 결과처럼 순서를 보장하지 않는 경우에는 기대 ID만 확인한다.

================================================================
1. 기본 기능 시연 — 하나의 새 mini-git 세션
================================================================

[D01] 저장소 초기화

입력:
init "Alice Kim"

기대값:
Initialized repository.
Current branch: main
Current user: Alice Kim

----------------------------------------------------------------

[D02] 커밋이 없는 브랜치 생성

입력:
branch archive

기대값:
Created branch: archive

현재 브랜치는 main으로 유지되고, archive는 아직 커밋을 가리키지 않는다.

----------------------------------------------------------------

[D03] main의 첫 커밋 생성

입력:
CoMmIt "Initial commit"

기대값:
[main CI_0] Initial commit

CI_0의 부모는 없다.

----------------------------------------------------------------

[D04] 현재 커밋에서 feature 브랜치 생성

입력:
branch feature

기대값:
Created branch: feature

main과 feature가 모두 CI_0을 가리키고, 현재 브랜치는 main으로 유지된다.

----------------------------------------------------------------

[D05] feature 브랜치로 전환

입력:
switch feature

기대값:
Branch switched: feature

----------------------------------------------------------------

[D06] feature의 첫 커밋 생성

입력:
commit "Add LOGIN feature"

기대값:
[feature CI_1] Add LOGIN feature

CI_1의 부모는 CI_0이다.

----------------------------------------------------------------

[D07] feature 이력 연장

입력:
commit "Fix login"

기대값:
[feature CI_2] Fix login

CI_2의 부모는 CI_1이다.

----------------------------------------------------------------

[D08] main 브랜치로 복귀

입력:
switch main

기대값:
Branch switched: main

----------------------------------------------------------------

[D09] main에서 별도 커밋 생성

입력:
commit "Add payment feature"

기대값:
[main CI_3] Add payment feature

CI_3의 부모는 CI_0이다.

----------------------------------------------------------------

[D10] 부모 우선 로그

입력:
log

기대 ID 순서:
CI_0 → CI_3 → CI_1 → CI_2

기대 관계:
CI_0은 CI_1과 CI_3보다 먼저 출력된다.
CI_1은 CI_2보다 먼저 출력된다.

각 커밋은 다음 형식으로 출력된다.
commit <ID> (Alice Kim, <실행 시각>)
<커밋 메시지>

----------------------------------------------------------------

[D11] 서로 다른 가지 사이의 최단 경로

입력:
path CI_2 CI_3

기대값:
Path: CI_2 -> CI_1 -> CI_0 -> CI_3

----------------------------------------------------------------

[D12] 조상 탐색

입력:
ancestors CI_2

기대 ID 순서:
CI_0 → CI_1

CI_2 자신은 결과에 포함되지 않는다.

----------------------------------------------------------------

[D13] 대소문자를 정규화한 키워드 검색

입력:
search LOGIN

기대 ID:
CI_1, CI_2

두 커밋의 출력 순서는 고정되지 않는다.

----------------------------------------------------------------

[D14] 여러 토큰의 AND 검색

입력:
search "login feature"

기대 ID:
CI_1

CI_1의 메시지만 login과 feature 두 토큰을 모두 포함한다.

----------------------------------------------------------------

[D15] 공백이 있는 작성자 검색

입력:
search --author="Alice Kim"

기대 ID:
CI_0, CI_1, CI_2, CI_3

네 커밋의 출력 순서는 고정되지 않는다.

----------------------------------------------------------------

[D16] 커밋이 없는 archive 브랜치로 전환

입력:
switch archive

기대값:
Branch switched: archive

----------------------------------------------------------------

[D17] 다른 이력과 연결되지 않은 루트 생성

입력:
commit "Separate history"

기대값:
[archive CI_4] Separate history

CI_4의 부모는 없다.

----------------------------------------------------------------

[D18] 연결되지 않은 커밋 사이의 경로

입력:
path CI_0 CI_4

기대값:
No path

----------------------------------------------------------------

[D19] 같은 커밋으로 가는 경로

입력:
path CI_0 CI_0

기대값:
Path: CI_0

----------------------------------------------------------------

[D20] 존재하지 않는 브랜치

입력:
switch missing

기대값:
[오류] 존재하지 않는 브랜치입니다: missing

오류 후에도 현재 브랜치는 archive로 유지되고 다음 명령을 입력할 수 있다.

----------------------------------------------------------------

[D21] 존재하지 않는 도착 커밋 ID

입력:
path CI_0 missing

기대값:
[오류] 존재하지 않는 End Commit ID로 조회를 시도했습니다: missing

----------------------------------------------------------------

[D22] 허용되지 않은 정렬 옵션

입력:
log --sort-by=hash

기대값:
[오류] 잘못된 정렬 기준값이 들어왔습니다.

----------------------------------------------------------------

[D23] 날짜 오름차순 로그

입력:
log --sort-by=date

기대 ID 순서:
CI_0 → CI_1 → CI_2 → CI_3 → CI_4

커밋 생성 시각이 같은 경우에도 안정 정렬에 따라 기존 저장 순서가 유지된다.

----------------------------------------------------------------

[D24] 작성자 오름차순 로그

입력:
log --sort-by=author

기대 ID 순서:
CI_0 → CI_1 → CI_2 → CI_3 → CI_4

모든 작성자가 Alice Kim으로 같으므로 안정 정렬에 따라 기존 저장 순서가 유지된다.

----------------------------------------------------------------

[D25] REPL 종료

입력:
exit

기대값:
별도 출력 없이 mini-git 프로그램이 종료된다.

================================================================
2. 입력 경계 확인 — 별도의 새 mini-git 세션
================================================================

[E01] 초기화 전 LOG

입력:
log

기대값:
[오류] Repository가 초기화되지 않았습니다.

----------------------------------------------------------------

[E02] 저장소 초기화

입력:
init "Alice Kim"

기대값:
Initialized repository.
Current branch: main
Current user: Alice Kim

----------------------------------------------------------------

[E03] 빈 저장소의 LOG

입력:
log

기대값:
로그 내용 없이 다음 mini-git> 프롬프트가 표시된다.

----------------------------------------------------------------

[E04] 결과가 없는 키워드 검색

입력:
search nothing

기대값:
검색 결과 없이 다음 mini-git> 프롬프트가 표시된다.

----------------------------------------------------------------

[E05] 빈 커밋 메시지

입력:
commit ""

기대값:
[오류] 커밋 메시지가 비어있습니다.

----------------------------------------------------------------

[E06] 닫히지 않은 따옴표

입력:
commit "Unclosed

기대값:
[오류] No closing quotation

----------------------------------------------------------------

[E07] 오류 후 정상 커밋 생성

입력:
commit "Valid message"

기대값:
[main CI_0] Valid message

앞선 오류들이 ID를 소비하지 않았으므로 첫 커밋 ID는 CI_0이다.

----------------------------------------------------------------

[E08] 루트 커밋의 조상

입력:
ancestors CI_0

기대값:
조상 내용 없이 다음 mini-git> 프롬프트가 표시된다.

----------------------------------------------------------------

[E09] 존재하지 않는 키워드 검색

입력:
search absent

기대값:
검색 결과 없이 다음 mini-git> 프롬프트가 표시된다.

----------------------------------------------------------------

[E10] 부분 문자열 검색

입력:
search mess

기대값:
검색 결과 없이 다음 mini-git> 프롬프트가 표시된다.

`mess`는 커밋 메시지의 전체 토큰인 `message`와 일치하지 않는다.

----------------------------------------------------------------

[E11] 대소문자가 다른 작성자 검색

입력:
search --author="alice kim"

기대값:
검색 결과 없이 다음 mini-git> 프롬프트가 표시된다.

작성자 검색은 대소문자를 정확히 구분한다.

----------------------------------------------------------------

[E12] 반복 INIT

입력:
init Bob

기대값:
[오류] 이미 초기화가 완료된 Repository입니다.

----------------------------------------------------------------

[E13] 중복 브랜치 이름

입력:
branch main

기대값:
[오류] 이미 존재하는 브랜치 이름입니다: main

----------------------------------------------------------------

[E14] 비어 있는 정렬 기준

입력:
log --sort-by=

기대값:
[오류] 정렬 기준값이 비었습니다.

----------------------------------------------------------------

[E15] 비어 있는 작성자 이름

입력:
search --author=

기대값:
[오류] 이름이 비어있습니다.

----------------------------------------------------------------

[E16] 따옴표 없이 공백을 포함한 검색어

입력:
search login feature

기대값:
[오류] 인자의 개수가 잘못됐습니다; 입력:2, 필요:{1}

----------------------------------------------------------------

[E17] 존재하지 않는 명령

입력:
unknown

기대값:
[오류] 존재하지 않는 커맨드를 입력했습니다.

----------------------------------------------------------------

[E18] 종료 명령에 불필요한 인자 전달

입력:
exit now

기대값:
[오류] 인자의 개수가 잘못됐습니다; 입력:1, 필요:{0}

프로그램은 종료되지 않고 다음 명령을 입력받는다.

----------------------------------------------------------------

[E19] 오류 후 저장소 상태 유지 확인

입력:
log

기대 ID:
CI_0

기대 로그:
commit CI_0 (Alice Kim, <실행 시각>)
Valid message

----------------------------------------------------------------

[E20] QUIT으로 종료

입력:
quit

기대값:
별도 출력 없이 mini-git 프로그램이 종료된다.
